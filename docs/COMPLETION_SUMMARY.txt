📚 ANSWERING THE 6 KEY QUESTIONS
═══════════════════════════════════════════════════════════════════════════

All detailed answers are in docs/DEMO.md:

Q1: Where does each piece of data come from?
A1: /proc/, /var/log/, filesystem — all native Linux sources

Q2: What's the difference between HIDS and NIDS?
A2: HIDS = host state (processes, files). NIDS = network traffic.

Q3: How would an attacker evade this?
A3: Clear logs? We have baseline. Modify files? We detect changes.

Q4: Hardest design decision?
A4: Baseline vs absolute thresholds. Solution: Use both where appropriate.

Q5: How to reduce false positives?
A5: Whitelists, cooldown, baseline comparison, severity levels.

Q6: What would you build next?
A6: Trending, remote logging, rootkit detection, live dashboard.


🎓 WHAT YOU LEARNED BUILDING THIS
═══════════════════════════════════════════════════════════════════════════

1. Security Tools are 10% detection, 90% noise management
2. Baselines are more powerful than absolute thresholds
3. Defense in depth: use HIDS + NIDS + firewall + EDR
4. Structured logging (JSON) is essential for automation
5. Configuration over hardcoding makes tools flexible
6. Alert cooldown prevents fatigue and wasted work
